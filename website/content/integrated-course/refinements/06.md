## Limit inputs to fit the work in front of you
QUESTION: Which incoming information is useful for this task, and which only creates activity?
CORE: More input can improve a decision until it overwhelms the attention needed to use it. Before a focused session, name the question and the sources or messages required now. Keep a place to capture other items for later review. An input limit is a temporary design for the task, not a rule to ignore responsibilities or people. Afterward, check whether the limit helped the work and whether anything important was missed.
CONNECT: [[11 Evidence, science, and causal claims]] asks for relevant evidence. [[04 Agency, responsibility, and boundaries]] helps agree on availability where others depend on you.
EXAMPLE: A writer drafts a proposal with the brief and two reference documents open, while placing unrelated messages in a scheduled review window.
DO: For one work block, list the inputs needed and two common inputs to defer.
TRY: Set a clear route for urgent matters that genuinely cannot wait.
REFLECT: Which source felt productive merely because it arrived during the session?
CHECK: What is a task-specific input limit?::A temporary choice to admit information needed for the current question while routing other inputs to a later review.
MODEL: Define~Name the task's question.|Filter~Allow relevant inputs.|Review~Check benefit and missed obligations.

## Count the cost of switching tasks
QUESTION: What happens when I repeatedly leave a difficult task and return?
CORE: Switching can be necessary, but every restart may require recovering context, remembering a decision, and resisting the next interruption. Track a short period before declaring yourself incapable of focus. Group related tasks where possible, write a restart cue before leaving, and agree on an interruption route with people who need you. The point is to reduce avoidable switching while preserving responsiveness to real needs.
CONNECT: [[07 Learning, memory, and understanding]] uses retrieval cues. [[22 Planning, collaboration, and delivery]] makes handoffs and interruptions visible.
EXAMPLE: An analyst writes the next calculation and open question before pausing for a meeting; the note cuts the time needed to resume.
DO: Count task switches in one ordinary work period and note what triggered each.
TRY: Write a one-line restart cue before the next planned interruption.
REFLECT: Which switch was unavoidable, and which did I use to escape uncertainty?
CHECK: Why record a restart cue before switching?::It preserves the next step and unresolved context so returning requires less reconstruction.
MODEL: Observe~Count switches and triggers.|Prepare~Leave a restart cue.|Adjust~Group or route avoidable interruptions.
